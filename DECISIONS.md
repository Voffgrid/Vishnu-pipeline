Append-only record of non-obvious choices made during the build. New entries on top.

## 2026-05-12 — Phase 0

### Next.js 16 instead of 15
`PLAN.md` calls for Next.js 15, but `create-next-app@latest` ships 16.2.6 as of today. Going with the latest — no reason to pin to a deprecated major. The `AGENTS.md` file generated by the scaffold explicitly warns that APIs and conventions may differ from training-data Next.js 15; we read the bundled docs in `node_modules/next/dist/docs/` when in doubt.

### App scaffolded into repo root (no `script-to-video/` subfolder)
PLAN's literal command was `npx create-next-app script-to-video`. User confirmed they want the Next.js app to live directly at the repo root (`/Users/shanmukhram/Desktop/Vishnu`) so `prd.md` and `PLAN.md` sit alongside `src/`. Workaround: scaffolded to a temp `vishnu-app/` (npm rejects capital letters, so we couldn't pass `.` with the dir name "Vishnu") and moved files up; package name set to `vishnu`.

### Worker platform: Inngest (deferred decision)
PLAN §9.1 of `prd.md` lists three worker options. We're going with Inngest for Phase 0/1 because the durable-functions model eliminates queue/retry boilerplate and the free tier covers v1 volume. We'll revisit on Day 1 of Phase 2 if FFmpeg can't run in the Inngest sandbox — fallback is a small Railway service exposing `POST /stitch`.

### Inngest app id = `vishnu`
Chose the project shortname over `script-to-video-pipeline` for terseness in the Inngest dashboard.

### `--no-turbopack` on scaffold
Default scaffold attempted to enable Turbopack. Disabled for Phase 0 to keep the dev experience boring and predictable. Can re-enable later once everything else is stable.
